# Architecture — Jarvis Modular Monolith & Multi-Agent AI OS (P10 Hardened)

One local-first FastAPI process (`127.0.0.1:4700`) orchestrates real-time voice I/O, the React + TypeScript offline UI (`apps/frontend/dist`, with legacy fallback at `/legacy`), local Ollama inference (`127.0.0.1:11434`), SQLAlchemy/Alembic persistence (PostgreSQL 18 + native `pgvector` or local SQLite WAL), LangGraph stateful multi-agent workflows, sandboxed Dev Workforce integrations (`graphify`, `opencode`, `git worktree`), controlled knowledge & model lifecycle pipelines, and 3-2-1 authenticated disaster recovery.

```text
React UI (apps/frontend/)  <--HTTP/SSE-->  jarvis/api.py + api_deps.py + api_v2.py + api_skills.py
                                               |-- Assistant (assistant.py) -> EventBus (core/event_bus.py) + ResourceGovernor (core/resources.py)
                                               |-- Voice Pipeline: voice.py, stt.py, tts.py, aec.py, wakeword.py, translator.py
                                               |-- 3-Layer Decision Engine: decision/{rules,classifier,router}.py
                                               |-- Multi-Model Gateway: gateway/{gateway,providers,interface,sandbox_proxy}.py + netsec.safe_stream_lines + brain.py
                                               |-- Agent Skills Manager: skills/{registry,metadata,security,compatibility,validator,discovery,router,recommended_audit}.py
                                               |-- 5-Way Memory & DB: db/{engine,models,targets,migrations} + memory/{embeddings,vectors,five_way,legacy_migrator}.py
                                               |-- Personal Assistant Dept: departments/assistant/{documents,reminders,productivity}.py
                                               |-- AI Dev Workforce Dept: departments/dev/workforce.py + integrations/{graphify_adapter,opencode_adapter,git_worktree}.py + deploy/opencode.Dockerfile
                                               |-- LangGraph Agents & Approvals: agents/{orchestrator,assistant_graph,workforce_graph,checkpointer,approvals}.py
                                               |-- Learning & Registry: learning/{knowledge_pipeline,feedback,evaluation}.py + learning/training/
                                               |-- Security & Secrets: security/{secrets,pii_firewall}.py + audit.py + netsec.py
                                               `-- Disaster Recovery: recovery/backup.py + scripts/bootstrap.ps1
```

## Key Subsystems & P10 Hardening

1. **Dependency Injection & Resource Governance (`jarvis/api_deps.py`, `jarvis/core/resources.py`)**: All routers resolve `app.state.a` dynamically via FastAPI `Depends`; canonical domain errors map via [`jarvis/core/errors.py`](jarvis/core/errors.py). [`ResourceGovernor`](jarvis/core/resources.py) caps concurrent local Ollama heavy inference (`max_local_concurrency=1`) and queue depth to protect GTX 1650 4 GB VRAM and 16 GB system RAM.
2. **Real PostgreSQL + `pgvector` & Embeddings (`jarvis/db/`, `jarvis/memory/`)**:
   - [`VectorStore`](jarvis/memory/vectors.py) provides `SQLiteVectorStore` locally and `PgVectorStore` (native PostgreSQL `vector(dim)` columns, `HNSW`/`IVFFlat` indexes, database-side `<=>`/`<->`/`<#>` similarity operators, SQL expiry & JSONB metadata filtering without full-table Python scans).
   - [`EmbeddingProvider`](jarvis/memory/embeddings.py) decouples local Ollama (`/api/embed`), local Hugging Face, and explicitly versioned deterministic `hash-v1:256` fallback while rejecting mismatched vector dimensions or incompatible models.
   - [`FiveWayMemoryService`](jarvis/memory/five_way.py) enforces `project_id` isolation, vector+SQL expiry filtering, scheduled `purge_expired()`, duplicate detection without blind auto-merge, explicit supersession, audit trails, and configurable multi-factor ranking. [`migrate_sqlite_to_postgres`](jarvis/memory/legacy_migrator.py) migrates records/vectors non-destructively with count & dimension verification.
3. **3-Layer Decision & Streaming Gateway (`jarvis/decision/`, `jarvis/gateway/`)**:
   - Real chunk-by-chunk SSE streaming across OpenAI-compatible, Gemini (`+ tools`), Anthropic, and Ollama via `safe_stream_lines` in [`jarvis/netsec.py`](jarvis/netsec.py).
   - Dynamic capability registry (`require_streaming`, `require_tools`, `require_vision`, `json_mode`, and full `est_prompt_tokens + max_tokens <= max_ctx` context gating), explicit rejection (`CloudGatewayError`) without silent primary bypass when no candidate qualifies, circuit breakers, exponential backoff with jitter, cancellation tokens, paid-model lock (`providers.allow_paid_models=false`), and mandatory central egress PII/secret + project privacy firewall (`ModelGateway.enforce_egress_firewall`).
4. **Hardened Development Workforce (`jarvis/agents/workforce_graph.py`, `jarvis/integrations/git_worktree.py`, `jarvis/integrations/opencode_adapter.py`, `jarvis/departments/dev/workforce.py`)**:
   - Explicit 12-state DAG (`PLANNING` -> `RUNNING` -> `QA_PENDING`/`QA_FAILED` -> `SECURITY_REVIEW` -> `APPROVAL_PENDING` -> `APPROVED` -> `MERGING` -> `COMPLETED` / `BLOCKED` / `FAILED` / `CANCELLED`) with `validate_transition`, durable cancellation checkpoints between nodes (`is_run_cancelled`), real active subprocess/container tree termination via `cancel_run_processes`, worktree preservation unless cleanup authorized, blocked approval/resume for cancelled runs, and `asyncio.to_thread` FastAPI execution.
   - Complete `base_sha..HEAD` change manifest (`build_change_manifest`) covering committed changes, staged/unstaged edits, untracked files, renames (`old_path`/`new_path`), deletions, file modes, symlinks, and binary hashes, paired with streaming file scanning (`_scan_file_streaming`, `2 MB` max bound with mandatory blocking for oversized files — zero silent 100 KB truncation). Approvals pin `base_sha`, `head_sha`, `manifest_sha256`, `diff_hash`, and `approval_fingerprint`.
   - [`ExecutionPolicy`](jarvis/integrations/git_worktree.py) and `opencode_adapter.run_opencode_task` target the pinned [`deploy/opencode.Dockerfile`](deploy/opencode.Dockerfile) image (`jarvis-opencode:1.19.5`, Node 22 + OpenCode `1.19.5` verified via npm SHA-512 SRI hashes, UID `10001:10001`, `--read-only`, `--cap-drop=ALL`, `--security-opt=no-new-privileges:true`, `--pids-limit=256`), enforce 4 explicit network policies (`offline`, `model_gateway` with single-run `ScopedGatewayTokenManager` & `/api/v2/sandbox/v1/*`, `restricted_egress` with `RestrictedEgressProxy`, and owner-authorized `unrestricted`), convert Windows mount paths safely, and refuse silent unisolated host fallback unless `allow_host_fallback=True`.
5. **Agent Skills & Capabilities Manager (`jarvis/skills/`, `jarvis/api_skills.py`, `apps/frontend/src/features/SkillsPanel.tsx`)**:
   - Canonical DB-backed central registry (`SkillRow`, `SkillVersionRow`, `SkillAssignmentRow`, `SkillMetricRow` via `0003_p10_12_skills_and_targets`) storing validated skills in isolated versioned directories (`data/skills/installed/<skill_id>/<version>/`).
   - Enforces license verification, directory SHA-256 checksums, malicious script/prompt-override blocking, quarantined scripts (`allow_untrusted_scripts=false`), runtime compatibility adapters (`jarvis_native`, `opencode`, `claude_code`, `codex`), dynamic task/context-budget routing (`AgentCapabilityRouter`), strict `<jarvis_skill policy_precedence="jarvis_system_first">` precedence, and invocation/QA quality delta tracking.
6. **Controlled Learning & Registry (`jarvis/learning/`)**:
   - RAG knowledge updates (`KnowledgePipeline`) are separated from optional weight training (`TrainingManager`, off by default). Enforces license verification (`allowed_licenses`), prompt-injection rejection (`detect_poisoning`), `<retrieved_knowledge untrusted_data="true">` quarantine delimiters, global cross-source chunk deduplication, vector sync (`external_knowledge`), remote training bundle delegation (`prepare_remote_delegation_bundle`), mandatory 12-category evaluation before candidate promotion, `auto_promote=false` lock, and atomic rollback.
   - `TrainingManager.start_job()` defaults to `force_spawn_even_if_blocked=False`, requires live package & hardware clearance (missing required packages cannot be overridden; hardware limits require explicit audited `override_reason` + `actor`), enforces single active job concurrency (`worker.pid`), kills worker trees on cancel, and `training_worker.py` enforces real `BitsAndBytesConfig` 4-bit/8-bit quantization (refusing silent FP32 fallback).
7. **3-2-1 Authenticated Disaster Recovery & Target Protection (`jarvis/db/targets.py`, `jarvis/recovery/backup.py`, `scripts/bootstrap.ps1`)**:
   - [`DatabaseTargetRegistry`](jarvis/db/targets.py) normalizes DB identities (`driver://host:port/database`, zero plaintext passwords) across SQLite & remote PostgreSQL targets so even SQLite-backed Jarvis protects registered/live/unknown PostgreSQL production databases. Multi-step API restore (`/api/v2/recovery/restore/request-production` -> approval -> `/execute`) requires single-use `ApprovalRequestRow` tokens; `/verify` strictly requires isolated `scratch_pg` targets.
   - Supports SQLite online backup + PostgreSQL native `pg_dump`/`pg_restore` via temporary `PGPASSFILE` (never CLI password argv, scrubbed errors, `--exit-on-error`, strict zero exit required), cross-dialect JSONL snapshots, tracked + untracked repository archival & `restore_repositories()` with overwrite protection, AES-256-GCM DPAPI + `.jvault` encryption, HMAC-SHA256 manifests, and explicit `database_and_app_state_only` vs `full_recovery_complete` reporting.
