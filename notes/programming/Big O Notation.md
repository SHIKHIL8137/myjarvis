# Big O Notation

Big O describes how running time or memory grows with input size n. O(1) is constant, O(log n) is binary search, O(n) is a single scan, O(n log n) is good sorting, O(n^2) is nested loops. Prefer hash maps for lookups. Scoring every note against a query is O(n), fine for thousands of notes, which is why [[Vector Embeddings]] indexes only matter later. See also [[SQL Joins]] for query cost.
